Live Stage Toolkit

Набор инструментов для создания систем захвата движений (без использования маркеров) и вывода визуального контента в реальном времени для театральных постановок на базе Unreal Engine 5.

Эти инструменты были разработаны для спектакля «Queen Anne», в котором живые танцоры управляют цифровыми персонажами, отрисовываемыми в реальном времени и проецируемыми на сцену. Мы публикуем их, чтобы независимым театрам не приходилось заново «изобретать велосипед», проходя через череду неудач.

Зачем это нужно

Системы захвата движений без маркеров отлично работают в студии, но театр — это не студия.
На сцене темно, свет мерцает, осветительные приборы меняют цвета каждые несколько секунд, а исполнители двигаются быстро. На большинство вопросов, определяющих работоспособность такой системы, можно ответить с помощью простых расчетов еще до того, как будут потрачены деньги:

Сколько нужно камер, с каким фокусным расстоянием и на какой высоте их разместить?
Сколько пикселей будет занимать фигура исполнителя (по высоте) в самом дальнем углу сцены?
Насколько короткой должна быть выдержка, чтобы избежать смазывания движения, и какой уровень освещенности для этого потребуется?
Сможет ли сеть передать потоки данных со всех камер?
Насколько ярким будет изображение, проецируемое на конкретную поверхность?
Какую задержку (латентность) увидит зритель?

Этот набор инструментов позволяет получить численные ответы на данные вопросы, а также предоставляет компоненты, необходимые для надежного проведения представления.

Инструменты
tools/stage_rig_calculator.py

Рассчитывает технические параметры системы захвата движений и проекции для сцены.
Не требует никаких зависимостей, кроме стандартной библиотеки Python. Пример расчетных данных для зоны захвата 5 × 5 м при использовании камер с разрешением 5 Мп и глобальным затвором (global shutter):

Расстояние (ближняя / средняя / дальняя точка) ... 3,57 / 5,50 / 9,18 м
Требуемый горизонтальный угол обзора (FOV) ....... 70,5°
Рекомендуемое фокусное расстояние ............... 6,0 мм
Высота объекта (в пикселях) в дальней точке ..... 339 пкс
Макс. выдержка (для размытия в 2 пкс) ............ 1,76 мс
Требуемая освещенность сцены .................... 64 лк
Сетевая нагрузка на одну камеру .................. 2,406 Гбит/с
Сквозная задержка (end-to-end latency) ........... 187,7 мс

Запуск:

python3 stage_rig_calculator.py --width 7 --depth 6 --rig-height 4.5 \
--performers 4 --cameras 6 --preset imx250 --fps 60

Самопроверка:

python3 stage_rig_calculator.py --selftest
tools/artnet_probe.py

Инструмент контроля качества сети для шоу. Прослушивает порт UDP 6454, декодирует пакеты Art-Net DMX
и для каждой вселенной (universe) выводит отчет: фактическую частоту обновления,
пропущенные кадры (определяемые по полю последовательности), дубликаты,
пакеты, пришедшие не по порядку, и перцентили межкадрового интервала.

Предназначен для запуска перед каждой репетицией. Если интервал на уровне
99-го перцентиля превышает длительность полутора кадров DMX, световые приборы
будут заметно «дергаться» (работать с рывками).

python3 artnet_probe.py --seconds 30 --nominal-hz 44
unreal/ShowNet/

Подсистема Unreal Engine для детерминированного вывода данных по протоколу Art-Net.
Отправка DMX из игрового потока (game thread) означает, что любой «фриз» рендеринга
приведет к сбою освещения на глазах у зрителей. Этот компонент переносит вывод
в изолированный поток с фиксированной частотой и использует: двойную буферизацию
данных каналов; сторожевой таймер (watchdog), гасящий все вселенные при зависании
игрового потока; функцию аварийной остановки с фиксацией состояния; а также
три кадра гашения при завершении работы, чтобы ни один прибор не остался
включенным с устаревшим значением сигнала.

Важная информация перед покупкой оборудования

Используйте сенсоры с глобальным затвором (global shutter). Яркость сценических светодиодных прожекторов регулируется методом широтно-импульсной модуляции (ШИМ) с частотой от сотен до тысяч герц. Сенсор с построчным считыванием (rolling shutter) экспонирует каждую строку в разной фазе этого цикла, что приводит к появлению полос на изображении. Сенсор с глобальным затвором (global shutter) экспонирует все пиксели одновременно, поэтому причина возникновения полос отсутствует.

Использование ближнего инфракрасного диапазона. При реалистичной скорости движения рук танцора (6 м/с) ограничение размытия в движении двумя пикселями требует, чтобы время экспозиции не превышало примерно 1,76 мс, — а для этого нужно гораздо больше света, чем может обеспечить затемненная сцена. Инфракрасная подсветка (850 нм) в сочетании с полосовыми фильтрами на объективах полностью исключает влияние сценического освещения на процесс съемки. Художник по свету получает полную свободу действий.

Аппаратная синхронизация. Рассинхронизация камер всего на 5 мс приводит к смещению руки, движущейся со скоростью 6 м/с, на 30 мм, чего достаточно для нарушения работы метода триангуляции. Аппаратная синхронизация (genlock) позволяет снизить эту погрешность до долей миллиметра, в отличие от программного выравнивания кадров.

Проверьте сеть перед выбором камер. Монохромный сенсор с разрешением 5 Мп и частотой 60 кадров/с генерирует поток данных 2,4 Гбит/с. Это превышает пропускную способность гигабитного канала. Придется изменить либо разрешение, либо частоту кадров, либо интерфейс; лучше выяснить это с помощью расчетов, чем уже после оформления заказа.

Статус

Ранняя стадия разработки. Инструменты используются в реальной работе над проектом, для которого они были созданы. Калькулятор и диагностический модуль оснащены функциями самопроверки. Приветствуются сообщения об ошибках и запросы на внесение изменений (pull requests).
